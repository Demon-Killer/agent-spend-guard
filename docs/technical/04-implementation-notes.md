# 实现说明

## 第一版推荐技术栈

如果环境允许，后端第一版建议使用 Go，除非有明确理由不用。

原因：

- 足够适合代理服务。
- 单二进制部署简单。
- 标准库 HTTP 和 streaming 能力强。
- 相比 C++，更适合快速验证工具型产品。

前端：

- 使用最小 React 或 Vue。
- UI 保持工具化和实用。
- 用户验证前不要过度打磨视觉。

数据库：

- MVP 使用 SQLite。
- 一个本地文件足够。

## Streaming 代理注意事项

代理必须保留 Server-Sent Events 流式响应。

重点：

- 及时 flush chunk。
- 不要等完整响应结束后才返回客户端。
- 能拿到 usage 时在流结束后记录。
- 如果没有 usage，先记录请求元数据，后续再估算。

## 预算检查注意事项

预检查：

- 如果今日/月度花费已经超过限制，直接拒绝请求。

请求后记录：

- 响应结束后记录估算费用。
- 可能出现“本次请求完成后才超过预算”的情况。
- 下一次请求必须被阻断。

后续优化：

- 请求前按最大预估成本做额度预占。

## 隐私默认值

默认行为：

- 不持久化 prompt messages。
- 不持久化模型输出。
- 只记录元数据。

未来可选 debug 模式：

- 用户可以显式开启本地 prompt 日志。
- 默认必须关闭。
